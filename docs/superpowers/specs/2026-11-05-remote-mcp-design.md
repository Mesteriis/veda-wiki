# MCP по адресу сайта для других людей — проект

Дата: 2026-11-05. Решения владельца: другие люди подключают агентов по домену и
ключу; **через сеть — только чтение**. Запись остаётся только в локальной среде
владельца (`veda mcp --editor` через SSH). Сейчас для чтения постороннему нужен
бинарник `veda` у себя — это неудобно.

## Что получает человек

Владелец создаёт в «Настройках → Ключи доступа» обычный ключ чтения на нужные
источники и передаёт его человеку вместе с одной командой, например:

```sh
claude mcp add --transport http veda https://veda.sh-inc.dev/mcp --header "Authorization: Bearer <ключ>"
```

Ничего, кроме клиента, ставить не нужно. Агент видит 14 инструментов чтения и
только источники ключа. Записи и администрирования через сеть нет.

## Сервер

- **`/mcp`** — MCP по Streamable HTTP (транспорт `modelcontextprotocol/go-sdk`
  v1.8.0, без сессий, ответы JSON). Обслуживается приватными слушателями, в том
  числе TLS-слушателем за `veda.sh-inc.dev`; публичный слушатель — 404.
- **Аутентификация:** `Authorization: Bearer <ключ доступа>`. Принимаются только
  действующие ключи доступа. Ключ владельца и reader-токен на `/mcp`
  отклоняются. Без ключа или с неверным — 401 с `WWW-Authenticate: Bearer`.
- **Только чтение в двух местах:** MCP-сервер строится в режиме чтения (список
  инструментов как у `--reader-key-file`), а ключ доступа и так не может писать в
  REST (`Read-only access`). Запись не появится, даже если один из уровней
  ошибётся.
- **Как работает внутри:** на каждый запрос строится тот же MCP-сервер
  (`internal/mcp.NewServer`), его клиент обращается к REST-обработчику того же
  процесса в памяти с тем же ключом, поэтому видимость — ровно как у REST.
- **Активность:** вкладка «Активность» показывает режим «чтение по адресу»
  отдельно от локального чтения.
- **Лимит тела запроса** 1 МБ (MCP-запросы чтения маленькие).

## Интерфейс

«API и MCP → Подключение агентов»: способ **«По адресу и ключу»** — первым и по
умолчанию; прежний «чтение через локальный veda» остаётся, «редактор через SSH» —
только для владельца. Команды:

- Claude Code: `claude mcp add --transport http veda <адрес>/mcp --header "Authorization: Bearer <ключ>"`;
- Codex: `export VEDA_KEY=<ключ>` и `codex mcp add veda --url <адрес>/mcp --bearer-token-env-var VEDA_KEY`;
- OpenCode: `opencode mcp add --global veda --url <адрес>/mcp --header Authorization="Bearer <ключ>"`;
- Hermes: `hermes mcp add veda --url <адрес>/mcp --auth header`, заголовок
  `Authorization: Bearer <ключ>` по запросу (точный вид запроса не проверен —
  помечено в интерфейсе).

Ключ в команде — плейсхолдер `<ключ>`; поле для ключа на странице не хранится.

## Не цели

- Запись через сеть в любом виде.
- OAuth и самостоятельная регистрация.
- Ограничение частоты запросов (отдельная задача).

## Проверки

Go-тесты с официальным SDK-клиентом по Streamable HTTP: без ключа — 401; ключ
владельца — 401; ключ доступа — 14 инструментов, видны только его источники,
`veda_write_article` неизвестен; на публичном слушателе — 404. Фронтенд-тесты на
команды. После развёртывания — подключение Claude Code к
`https://veda.sh-inc.dev/mcp` временным ключом, который потом отзывается.
