# Внедрение графа знаний в VEDA — техническое задание владельца (2026-11-04)

Реализовать систему автоматического извлечения сущностей и отношений из статей, построения графа знаний, перекрёстной навигации между документами и выдачи подтверждённого контекста агентам через REST/MCP. Основа: локальная модель `fastino/gliner2.5-multi-v1`, отдельный Python-сервис извлечения, бизнес-логика на Go и Neo4j Community как производный графовый индекс. Интерфейс — существующий React/TypeScript VEDA. Нужна законченная интеграция с работающим основным сценарием, документацией и проверками. Обычные инженерные решения принимать самостоятельно; реальные противоречия с кодом или средой обозначать явно; не выдумывать доступ, результаты тестов или поддержку библиотек.

## 2. Пользовательский результат и границы

После включения функции существующие и новые статьи автоматически анализируются. Читатель может:
1. Открыть статью и увидеть извлечённые сущности, связанные статьи и объяснение каждой связи.
2. Переключить существующий экран графа между явными ссылками и графом знаний.
3. Выбрать сущность, увидеть её упоминания и отношения, перейти к документу и подтверждающей цитате.
4. Найти информацию через ограниченный контекст графа, доступный REST/MCP-клиентам.

У каждой извлечённой связи — проверяемое происхождение: источник, путь статьи, SHA текста и фрагмент. Автоматически найденные связи — производные данные; исходный Markdown и GitHub-репозитории не переписываются. Первый сценарий — уже импортированные Markdown-статьи. PDF, DOCX, OCR не заявлять. Предусмотреть границу преобразования документа в текст, но не расширять задачу до файлового хранилища или OCR. Не нужен чат-бот, генератор ответов, векторная БД или Microsoft GraphRAG; поиск по соседям не называть GraphRAG.

## 3. Архитектурные инварианты

- Приложение, REST, MCP, права и жизненный цикл статей — в Go. Python — только извлечение из переданного текста.
- React — интерфейс чтения. Индексацию, повторную обработку и конфигурацию запускают owner REST/MCP/CLI. Браузерные article/knowledge writes запрещены, включая браузер с административной сессией.
- Статья = `source_id + path`; совпадающие пути в разных источниках не объединяются.
- Авторитетное содержимое и права — в store VEDA. Neo4j не определяет права.
- Репозиторная видимость, публикация ревизии, scoped grants, истечение ключей и fail-closed сохраняются.
- Без включённого модуля VEDA работает как прежде, без Python, весов и Neo4j.
- Ошибка извлекателя или графовой БД не отменяет запись статьи, импорт и чтение; статус knowledge — недоступен/ожидает восстановления.
- Новые пакеты, владельцы данных и зависимости — в `docs/architecture.md` и architecture guard; проверки не отключать.
- Лимит 500 строк на файл, включая Python-модули (включить в проверки). Без god objects и параллельных реализаций одной операции в REST и MCP.

## 4. Компоненты и хранение

`internal/knowledge` с узкими интерфейсами извлекателя, индекса и фоновой обработки; HTTP/MCP — адаптеры; wiring и workers — `internal/app`. Разделение: контракты и сервис чтения; подготовка текста; сопоставление сущностей; manifest/reconciliation; worker; HTTP-клиент извлекателя; Neo4j-адаптер; модели ответов. Без циклических импортов.

Python-сервис: `services/knowledge-extractor/` — `pyproject.toml`, закреплённые зависимости/lock, типизированные схемы, загрузчик модели, адаптер результатов, обработка длинного текста, health/readiness, тесты. Модель грузится один раз на процесс; число процессов и параллельных inference ограничено.

Neo4j — восстанавливаемый индекс: документ, снимок текста, упоминание, сущность, извлечённое утверждение и его evidence. Не сводить утверждения к единственному ребру между глобальными сущностями: сохранять независимые основания, разные документы и противоречащие утверждения. Идентичность снимка: `source_id`, `path`, `content_sha256`, fingerprint pipeline (меняется при изменении checkpoint, extraction schema, preprocessing/chunking, правил entity resolution). Локальные ID модели (`e1`) — не глобальные ID.

Manifest, задачи и checkpoints — отдельно от `domain.Database`, например `<data>/knowledge.sqlite` через используемый SQLite-драйвер; не раздувать `state.json`. Свои миграции, восстановление задач, корректное закрытие, приватные права. Индекс и задачи восстанавливаются из VEDA; пользовательские правила/алиасы хранятся отдельно от удаляемого индекса. Не обещать атомарную транзакцию между VEDA, служебной БД и Neo4j: согласованность — сверка, идемпотентность, проверка снимков.

## 5. Извлекатель GLiNER2.5

Сверяться с актуальной документацией; загрузчик `from gliner2 import AutoExtractor`, `AutoExtractor.from_pretrained("fastino/gliner2.5-multi-v1")`. Выбрать документированный путь извлечения сущностей и отношений; допустим `JointIE`, если подходит; закрепить контракт тестами; `feasible=False` — неудовлетворённые ограничения, не пустой граф. Форматы `extract_relations` и `JointIE` различаются.

Сервис принимает только типизированные текстовые запросы от Go, возвращает нормализованный JSON; не читает пути, URL, Git, файлы. Схемы версионируются; размеры, таймауты, число одновременных запросов ограничены. `health` — живой процесс, `ready` — загруженная модель и работоспособный backend.

Настраиваемая компактная схема: люди, организации, проекты, сервисы, хосты, репозитории, технологии, документы. Отношения: `depends_on`, `runs_on`, `uses`, `part_of`, `maintained_by`, `documents` с семантикой и допустимыми типами концов; схема не требует всех типов в каждом тексте.

Длинные статьи — по структуре Markdown с перекрытием и проверкой реального token budget с учётом схемы; хвост не отбрасывать молча. Long-document helpers — только после проверки их поведения. Отношение, чьи концы не встретились в одном контексте, не выдумывать; связи между документами строит Go по подтверждённым упоминаниям.

Evidence: точный анализируемый текст и отображение координат в исходный Markdown. Единая семантика offsets: полуоткрытые диапазоны Unicode code points. Если preprocessing меняет текст — source map; иначе excerpt блока без ложной подсветки. Проверять границы спанов и совпадение с цитатой; повторяющиеся имена, overlap-дубликаты, кириллица, emoji, комбинируемые символы. Кодовые блоки и frontmatter не извлекать без явной политики.

Сохранять реальные model scores и их смысл; не называть вероятностью истинности. Утверждение — гипотеза с источником. Отрицания, планы, примеры, исторические состояния и противоречия — не безусловные текущие зависимости; при неопределённости — соответствующий статус и цитата, без непроверенной классификации.

CPU — базовый путь; MPS/CUDA — явной настройкой при доступности, ошибки и fallback честно. Офлайн: заранее подготовленная модель, закреплённый checkpoint, запуск без сети, понятная ошибка без cache. Не добавлять неподтверждённые аргументы загрузчика. Приватные статьи не отправлять внешним AI-провайдерам.

## 6. Entity resolution

Упоминание ≠ каноническая сущность. Автообъединение — по объяснимому правилу: устойчивый идентификатор, документированный технический ключ, явный alias. Одинакового имени человека, названия или косинусной близости недостаточно для слияния между источниками. Нормализация по типу; не склеивать латиницу и кириллицу. Неоднозначные совпадения — кандидаты. Правила и алиасы версионируются.

Различать в API и UI: явную Markdown-ссылку; упоминание одной сущности в нескольких статьях; извлечённое типизированное отношение; предположение о совпадении. Совместное упоминание ≠ `depends_on`. Для связанных статей — причина: общая доступная сущность, извлечённое отношение, подтверждающие фрагменты. Популярное общее слово не должно связывать всю wiki.

## 7. Фоновая индексация

Индексировать только принятое store VEDA. Python не обходит диск или GitHub. При старте и периодически сверять актуальные снимки с manifest: существующие статьи, REST/MCP-записи, локальный импорт, GitHub pull, разрешение конфликтов, копирование/перемещение, удаление, изменение публикации. Уведомления после commit допустимы, сверка обязательна.

`Tx.AfterCommit` выполняется под write lock: только быстрый неблокирующий сигнал.

Состояния задачи: pending/running/succeeded/failed/superseded; ограниченные retry с backoff, восстановление незавершённых, дедупликация по снимку и fingerprint. Очередь ограничена; переполнение не блокирует запись. Учесть pruning истории: не рассчитывать на номер ревизии; неизменяемый вход в очереди либо повторное получение активного снимка. Номера ревизий не вычислять через длину массива.

Worker берёт неизменяемую копию текста и освобождает lock до внешних вызовов; после извлечения проверяет актуальность. Публикация в Neo4j транзакционная; незавершённый набор не читается; повтор не создаёт дубликатов. Индексы и уникальные ограничения Community; параметры Cypher; типы отношений проверяются по схеме. Медленная старая задача не заменяет свежую: неизменяемые результаты по SHA и проверка снимка при чтении.

Активный `pipeline_fingerprint`: при смене — чтение на новую версию и переобработка; до готовности — состояние обработки; не смешивать схемы. Старую generation можно очистить. Поддержать два снимка: текущую и опубликованную ревизии (`Article.Published` отдельно от `Versions`), через функции чтения.

Удаление/перемещение и смена доступа сразу исключают данные из выдачи независимо от очистки Neo4j. Сверять manifest с исчезнувшими ключами (физическое удаление статьи/источника). Move может затронуть несколько статей. Уборка удаляет только потерявшее основания evidence, общая сущность остаётся, если на неё ссылается другой актуальный документ. Owner-операции: статус, повторная обработка статьи/источника, полная переиндексация — асинхронные, ограниченные, не меняют статьи.

## 8. Авторизация на уровне evidence

На каждом запросе — допустимые пары «документ + SHA видимого текста» и активный fingerprint из request-scoped store по правилам `ReadSnapshot`/`ReadPage`, `PublicRevision`, `SourcePublicReadable`. Не `source.visibility == public` и не глобальный store. Для `/api/v1` — вычисленный режим `public := !owner && !reader`; одного `h.Public` недостаточно. Публичный граф — по опубликованному SHA; не раскрывать номера приватных ревизий и bookkeeping публикации.

Набор разрешённых evidence ограничивает обход до вычисления результата. Запрещены скрытые промежуточные узлы, private evidence в основаниях, влияние скрытых документов на имена, aliases, counts, ranking, suggestions, summaries, метаданные кеша. Имя общей сущности и свойства — только из разрешённых оснований; одна доступная связь не открывает остальные. Слияние/alias, доказанное только скрытым документом, не связывает публичные документы.

Права, удаление, истечение ключа, отзыв grant, неполный импорт, истечение подтверждения GitHub-видимости — на чтении; индекс не продлевает доступ. Кеши привязаны к области чтения; logout/смена пользователя очищают клиентские данные, отменяют запросы, поздний ответ не восстанавливает их. Недоступные ID — not found. Игнорирование owner/reader credentials на публичном listener, Host checks, reader socket, запрет browser writes — сохранить. Neo4j и извлекатель недоступны из браузера; учётные данные на сервере; без endpoint произвольного Cypher.

## 9. REST, MCP, контекст

`/api/v1/knowledge/`: `GET entities` (поиск, лимит, пагинация), `GET entity`, `GET article`, `GET graph`, `GET context`, `GET status` (owner), `POST reindex` (owner, 202 с id операции). Лимиты: depth 1 (макс. 2), ≤200 узлов, ≤400 рёбер; `truncated`/пагинация; ограничение времени. Не грузить граф через `/api/state` в polling. Статистику backlog — только owner; статус доступной статьи можно вернуть с ней. Evidence: `source_id`, `path`, `content_sha256`, `pipeline_fingerprint`, цитата, id блока, координаты/anchor; различать raw model scores, тип связи, способ entity resolution. Контекст: лексический поиск + совпадения сущностей + ограниченный обход; evidence, пути, причины отбора, лимит размера; сервис не генерирует факты. Текст — недоверенные данные. `veda_context` и `AGENTS.md` не заменяются.

MCP read-tools: `veda_entities`, `veda_entity`, `veda_article_links`, `veda_graph`, `veda_graph_context`; owner: `veda_knowledge_status`, `veda_knowledge_reindex`. Общий Go-сервис через REST-клиент, строгие аргументы, лимиты, безопасные коды ошибок. Проверить `toolSpec.ReadOnly`, `refuseUnknown`, строгие схемы, прямой вызов tool; обновить `tools.json` и сценарии набора инструментов. Не расширять reader POST-исключение; reader/scoped key и socket не получают административных возможностей; существующие tools сохраняют контракт.

## 10. Интерфейс

Навигация через query parameters. Существующий UI и `styles/tokens.css`, без редизайна. На графе — переключатель «Ссылки» / «Граф знаний»; ссылки — прежнее поведение. В графе знаний: поиск сущности, фильтр источников и типов отношений, выбор центрального узла, масштаб, карточка элемента; документы и сущности различимы; направление и тип отношения читаемы. В карточке: документы, объяснение связи, цитата, переход к статье. В статье — блоки «Сущности» и «Связанные статьи»; честные подписи для кандидатов и извлечённых утверждений. Состояния: загрузка, пусто, модуль отключён, обработка, устаревший индекс, недоступная зависимость — без помех чтению; не показывать старые связи как актуальные при смене SHA. Серверные лимиты и постепенное раскрытие; допустима одна небольшая обоснованная библиотека графа. Клавиатурная навигация, узкий экран, текстовый список связей. Сеть — в `web/src/api`, строгие типы без `any`, CSS через `main.tsx`, цитаты — текстом, все действия — чтение.

## 12. Проверки

`make test` без скачивания модели и без Docker: детерминированный extractor и изолированный адаптер. Реальные интеграционные проверки — отдельной командой. Обязательные случаи: (1) выключенный knowledge — прежнее поведение; (2) одинаковые пути в разных источниках и неоднозначные имена не склеиваются; (3) повтор импорта/задачи без дубликатов, смена pipeline → переобработка; (4) новая ревизия исключает старые утверждения, медленный старый worker не возвращает их; (5) удаление/перемещение исключает evidence, общая сущность остаётся; (6) crash между записью статьи, сигналом, обработкой и записью графа исправляется reconciliation, незавершённая запись не видна; (7) недоступность GLiNER/Neo4j не ломает VEDA, retry/рестарт восстанавливают; (8) приватная текущая и публичная опубликованная ревизии дают разные корректные графы; (9) public listener игнорирует owner token, scoped key/team/user не видят чужих evidence, имён, counts, aliases, путей, подсказок; (10) истечение/отзыв доступа, смена visibility, partial import, просроченное подтверждение GitHub закрывают доступ без ожидания очистки; (11) reader MCP/socket и браузер не запускают owner mutations, прямой вызов запрещённого tool отклоняется; (12) кириллица, смешанные языки, emoji, повторные имена, Markdown, длинная статья — верные цитаты, хвост обработан, overlap без дублей; (13) граф и sidebar на desktop/узком экране, объяснение связей, переход к документу, logout и смена прав очищают данные.

Отдельный smoke: реальная GLiNER2.5, реальная Neo4j, REST и официальный MCP SDK на синтетических статьях; после подготовки cache — офлайн. Вручную размеченный набор ru/en технических примеров (отрицания, планы, одноимённые сущности), фактические ошибки и ограничения. Замеры индексации, чтения графа, ресурсов с условиями. `make test`, browser/MCP smoke, новые проверки модуля; недоступное — честно с командой.
